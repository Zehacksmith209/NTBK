ntbk · simulations

Write the physics. Watch it move.

An ntbk simulation is a few lines of text: the equations of motion as you'd write them in a textbook, the numbers with their units, and what to draw. ntbk solves the equations, checks the units, animates the drawing and graphs anything against anything.

# Mass on a spring
m*x'' + k*x = 0
m = 1 kg
k = 40 N/m
x(0) = 0.2 m
draw wall from (-1, 0.3) to (-1, -0.3)
draw spring from (-1, 0) to (x - 0.12, 0)
draw block at (x, 0) size 0.24 label "m"
1Insert → Simulate → Write the equations… puts a simulation on the page.
2Right-click → Edit (or double-click) opens its text.
3Type. Press ⌘ ↩ or click away to apply.
4Press Play in the bar under the ribbon.

01Your first simulation

A ball dropped from 20 m. Five lines of physics, two of drawing.

dropped ball
# Dropped ball
y'' = -g
g = 9.81 m/s^2
y(0) = 20 m
y'(0) = 0 m/s
stop when y <= 0
draw ground from (-3, 0) to (3, 0)
draw circle at (0, y) r 0.5 label "ball"

Line by line:

  • # Dropped ball is a comment. The first one names the simulation.
  • y'' = -g is the equation of motion: y's acceleration is −g. The '' means "rate of the rate", so y' is velocity and y'' acceleration.
  • g = 9.81 m/s^2 is an input. It gets a slider in the Edit panel.
  • y(0) = 20 m and y'(0) = 0 m/s are where it starts: 20 m up, at rest.
  • stop when y <= 0 ends the run when the ball reaches the ground.
  • The draw lines make the picture. The ball is drawn at (0, y), so it sits wherever y is at each instant. That one detail makes it move.

Play it: it lands at t = 2.02 s, which is √(2h/g). In the Edit panel the equation is typeset as ÿ = −g with a check mark: both sides in m/s².

02How a model is read

One statement per line. ntbk sorts each line by its shape; the order of lines doesn't matter.

The text is the record. Moving a slider rewrites its line (k = 60 N/m), and so does using a saved configuration. What you see in the text is always exactly what runs.

03Equations of motion

Write them the way the textbook does. ntbk works out the rest.

Rates

x' is how fast x changes (velocity if x is a position), x'' is how fast that changes (acceleration), and x''' goes one further. Any name can move: th, theta, x1, q for charge.

Any arrangement works

These all mean the same, and ntbk handles each one:

m*x'' + c*x' + k*x = F0*cos(w*t)
m*x'' = F0*cos(w*t) - c*x' - k*x
x'' = (F0*cos(w*t) - c*x' - k*x)/m

ntbk never rearranges your equation. At each step it finds the acceleration that makes both sides balance, so you can write forces on either side.

Several moving things

Write one equation for each moving quantity. They're solved together, so they can depend on each other, including each other's accelerations:

m*x1'' = -k*x1 + k*(x2 - x1)
m*x2'' = -k*(x2 - x1) - k*x2

The two rules

  • As many equations as moving quantities. Two equations, two names with rates. Otherwise ntbk says how many it found of each.
  • The highest rate must appear plainly, multiplied by things. m*x'' = … and (m + M)*x'' + m*L*th'' = … are fine. x''^2 = … or sin(x'') = … aren't. Almost every mechanics equation qualifies. Lower rates and positions can appear any way you like: sin(th), x'^2, x'*abs(x').

Time is t, in seconds, and can be used anywhere: F0*cos(w*t), 5 N/s * t.

04Inputs and sliders

A name set to a number becomes something you can change.

m = 2 kg
theta = 30 deg
mu = 0.2
L = 4 m
  • Each one appears under Inputs in the Edit panel with a text box and a slider. Typing 3 kg or dragging rewrites the line.
  • Units are optional but recommended: they're what makes the unit check work.
  • Notebook variables: a name defined in a Variables box on the page can be used directly. k = k_spring links the input to it, and a name you never define here, but which the notebook has, becomes an input automatically.
  • Configurations (controls bar) save the current inputs under a name. Use switches to them; Compare runs them alongside, drawn faintly and dashed on the graphs.

05Starting values

Every moving quantity starts somewhere. Anything you leave out starts at zero.

x(0) = 0.2 m        # where x starts
x'(0) = 0 m/s       # how fast it starts
  • For an equation with x'', you can set x(0) and x'(0). Setting x''(0) is an error, because the equation decides it.
  • A plain starting value gets a slider, like an input.
  • A starting value can use the inputs. Then it's worked out from them and follows their sliders, with no slider of its own:
v0 = 20 m/s
a = 45 deg
x'(0) = v0*cos(a)
y'(0) = v0*sin(a)

Change a and the launch direction changes with it. A starting value can't use a quantity that changes during the motion.

06Quantities and results

Anything defined from other things. Which kind it is depends only on what it uses.

Quantities can build on each other in any order: E = KE + U works whether KE is defined above or below it. A quantity that uses itself is an error. ntbk works out each one's unit (kg·m²/s² is shown as J), and that unit labels its graph axis.

Quantities are also how you keep drawings tidy. Work out a position once, then draw with it:

bx = L*sin(th)
by = -L*cos(th)
draw rod from (0, 0) to (bx, by)
draw circle at (bx, by) r 0.08

07Units

The unit check

Under each equation in the Edit panel:

  • ✓ both sides in N: the equation is consistent.
  • ⚠ left side in N, right side in N/m — they should agree: something is missing. Here, m*x'' = -k should be -k*x.

Radians count as a plain number, as in physics: ω/ωₙ has no unit, and an angle can go straight into sin(). An angular frequency (a name starting with omega or w) is shown in rad/s; other 1/s results are shown in Hz.

Always define g. g is a unit too (grams). ntbk won't guess, so write g = 9.81 m/s^2.

08Maths you can use

The usual calculator notation, from the mathjs library.

Comparisons< > <= >= == give 1 when true, 0 when false: F = k*(x > 0) pushes only when x is positive.
Logicand, or, not: stop when y < 0 and t > 0

Names

  • Letters, digits and underscores, starting with a letter: m, x1, Ff, vend. A name made of several letters is one name; Ff is not F times f.
  • Greek letters by name typeset as symbols: theta → θ, omega → ω, mu → μ, zeta → ζ.
  • Subscripts with an underscore: F_0 → F₀, omega_n → ωₙ. A trailing digit works too: F0 → F₀.
  • t, pi and e are taken. Don't use double underscores (x__1).

min and max are especially useful for physics that switches. Static friction can be written as Ff = min(mu*N, m*g*sin(theta)): it never pushes harder than needed to hold the block.

09Ending a run

Without an ending, a run goes on until you pause it.

stop when y < 0 and t > 0     # a projectile lands
stop when s >= L               # a block reaches the bottom of the slope
stop when t > 5                # five seconds

The run stops on the first step where the condition is true, which can be up to one time step past the exact moment (2 ms by default). After a run ends, Play starts it again from the beginning. Use t > 0 when the condition is already true at the start, as with a projectile launched from y = 0.

10Graphs

Any quantity against any other: time, positions, rates, energies, forces.

graph x                 # x against time
graph v                 # v against time
graph E                 # energy against time
graph v against x       # a phase portrait
graph F_s against x     # spring force against stretch
  • Every graph line is offered as a one-click chip above the graphs. The first three open with the box.
  • Without any graph lines, each moving quantity is graphed against time, with its phase portrait and the first few quantities as chips.
  • Graphable names: t, every moving quantity and its rates (x, x', x''), and every quantity.
  • On a graph, the two menus over its corner change what's up the side and along the bottom. + Graph adds one, and × removes one.
  • Pointing at an instant on one graph marks it on all of them. On an x–y graph it's a ring on the curve.
  • ⇥ Graphs panel also shows the graphs, taller and stacked, in a panel on the right. It can hold several simulations at once, each labelled by name and colour.
  • Graphs show in the controls bar picks the time window (last 10 s, or the whole run). Export CSV saves every recorded value with units.

11How drawing works

A draw line names a shape and where it goes. Where it goes can be any expression, and that's what animates it.

  • Points are written (x, y), and each part can be any expression: (L*sin(th), -L*cos(th)), (x - 0.06, 0.025).
  • The view fits itself. ntbk scales everything to fill the box, and the view only grows, so it never wobbles. Use view left bottom right top to fix it, for example view -2 -1 2 1.
  • Sizes are in the same units as positions. A block of size 0.24 is 0.24 m across, and it scales with everything else.
  • Lengths that show a quantity need a scale. An arrow for a 20 N force drawn by (F/20, 0) is 1 m long, so the 20 means "20 N per metre on screen". Pick whatever makes it readable.
  • Shapes are drawn in order: later lines on top.

12Every shape

Fourteen shapes. Words in brackets are optional.

Which side is hatched? Ground and walls are hatched on the right-hand side of the direction you draw them. Draw ground left to right for hatching underneath. Draw a wall top to bottom for hatching on its left, bottom to top for its right.

16What it can't do yet

Known gaps, so you don't lose time on them.

  • No equation, no run. A model must have at least one equation of motion. Motion written purely as a function of time (X = 2*cos(t), with no equation) isn't supported yet. As a workaround, add a dummy equation such as z'' = 0.
  • No collisions or contact. Bounces, stacking and rolling contact need a physics engine, which is planned. You can fake a floor with a stiff spring force: F = k*(-y)*(y < 0).
  • A fixed set of shapes. Pictures (draw image "car.svg"), pulleys and carts are planned.
  • Shapes can't be dragged in the view. Change positions in the text.
  • Fixed time step (2 ms by default; change it with Step in the controls bar). Very stiff systems may need a smaller step.
  • The view only grows during a run. A shape that flies far away leaves the drawing zoomed out until you press Reset. Use a view line to keep it fixed.
